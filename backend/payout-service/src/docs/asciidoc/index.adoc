이 문서는 컨트롤러 테스트(`ApiV1PayoutHoldControllerTest`, `ApiV1PayoutRecoveryControllerTest`, `ApiV1PayoutSellerControllerTest`, `InternalV1PayoutRefundControllerTest`)가 통과할 때 만들어진 요청·응답으로 채운다.
테스트가 실패하면 문서도 만들어지지 않으므로, 여기 있는 예시는 실제 응답과 같다.

[[overview]]
== 공통

* 성공·실패 응답은 모두 `{status, message, data}` 형식이다. 실패 응답의 `data`는 항상 `null`이다.
* 회원 ID는 `X-Member-Id` 헤더로 받는다. 관리자인지는 게이트웨이가 검사할 예정이며(PRO-20), 이 서비스는 헤더 값을 그대로 믿는다.

|===
| 상태 코드 | 뜻

| `400` | 입력값 검증 실패, 요청 본문 형식 오류, 경로 변수·헤더·쿼리 파라미터 형식 오류, 조회 기간 한도 초과
| `401` | `X-Member-Id` 헤더 없음
| `404` | 정산 내역, 지급보류 또는 회수 없음
| `409` | 지금 상태로는 처리할 수 없음 (이미 보류 중, 이미 지급 완료, 대회 취소로 닫힌 정산 내역, 이미 해제됨, 이미 완료된 회수, 다른 요청과 동시 수정)
|===

[[payout-recovery]]
== 회수 (관리자)

대회가 취소됐을 때 이미 지급한 정산금이 있으면, 정산 서비스가 대회 취소 이벤트를 받아 그 대회의 지급액 합만큼 회수를 대회당 1건 만든다.
판매자가 직접 입금하고, 관리자가 입금을 확인해 회수를 끝낸다. 지급 전 정산 내역은 회수 대신 취소(`CANCELED`)로 닫힌다.

[[payout-seller]]
== 정산 조회 (판매자)

`X-Member-Id`(회원 ID)를 회원 서비스에 물어 판매자 ID(판매자 신청서 ID)로 바꾸고, 그 판매자의 기록만 돌려준다.
승인된 판매자가 아니면(신청 없음 · 대기 · 반려) 403, 존재하지 않거나 탈퇴한 회원은 404, 회원 서비스에 묻지 못하면 503이다.
조회 기간은 나중에 바뀌지 않는 날짜로 자른다: 정산 내역은 정산 월, 건별 정산은 정산 대상일, 지급보류는 보류한 날.
지급 예정일은 보류를 풀면 바뀌므로 기간 기준으로 쓰지 않는다.

[[payout-internal]]
== 내부 API (서비스 간 호출 전용)

`/internal/**` 경로는 게이트웨이에 노출하지 않는다. 회원 ID 헤더를 받지 않는다.

[[payout-refund-eligibility]]
=== 참가권 환불 가능 여부 조회

대회일로 정산 대상일(대회 다음 날)을 구해, 오늘(한국 날짜)이 정산 대상일 전이면 환불 가능으로 돌려준다.
정산 대상일 당일부터는 사유와 상관없이(대회 취소·일정 변경 포함) 환불할 수 없다 (예: 대회 9/25 → 9/26부터 환불 불가).
환불 기한(판매자 지정) 판단은 주문 서비스가 하고, 이 API는 그 위의 상한선만 알려 준다.
주문 서비스가 환불 요청을 받을 때 동기 호출로 부르고, `data.refundable`이 `false`면 환불을 거절한다.
