이 문서는 컨트롤러 테스트(`ApiV1PayoutHoldControllerTest`, `InternalV1PayoutControllerTest`)가 통과할 때 만들어진 요청·응답으로 채운다.
테스트가 실패하면 문서도 만들어지지 않으므로, 여기 있는 예시는 실제 응답과 같다.

[[overview]]
== 공통

* 성공·실패 응답은 모두 `{status, message, data}` 형식이다. 실패 응답의 `data`는 항상 `null`이다.
* 회원 ID는 `X-Member-Id` 헤더로 받는다. 관리자인지는 게이트웨이가 검사할 예정이며(PRO-20), 이 서비스는 헤더 값을 그대로 믿는다.

|===
| 상태 코드 | 뜻

| `400` | 입력값 검증 실패, 요청 본문 형식 오류, 경로 변수·헤더 형식 오류
| `401` | `X-Member-Id` 헤더 없음
| `404` | 정산 내역 또는 지급보류 없음
| `409` | 지금 상태로는 처리할 수 없음 (이미 보류 중, 이미 지급 완료, 이미 해제됨, 다른 요청과 동시 수정)
|===

[[payout-hold-release]]
=== 지급보류 풀기

지급보류를 해제하고 정산 내역을 정산 예정(`CALCULATED`)으로 돌린다.
지급 예정일은 해제일 뒤 돌아오는 지급일(매월 20일, 휴일이면 다음 영업일)로 다시 정하며, 해제일이 지급일 당일이면 다음 달 지급일이다.

[[payout-internal]]
== 내부 API (서비스 간 호출 전용)

`/internal/**` 경로는 게이트웨이에 노출하지 않는다. 회원 ID 헤더를 받지 않는다.

[[payout-refund-eligibility]]
=== 참가권 환불 가능 여부 조회

대회일로 정산 대상일(대회 다음 날)을 구해, 오늘(한국 날짜)이 정산 대상일 전이면 환불 가능으로 돌려준다.
정산 대상일 당일부터는 판매자 승인 환불도 할 수 없다 (예: 대회 9/25 → 9/26부터 환불 불가).
주문 서비스가 환불 요청을 받을 때 동기 호출로 부르고, `data.refundable`이 `false`면 환불을 거절한다.
