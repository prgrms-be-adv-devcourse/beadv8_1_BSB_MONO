대회 등록·수정 테스트

product-service(8085)의 대회 등록·수정·취소 API를 직접 불러 보는 개발용 페이지입니다(dev 프로파일에서만 열립니다). 검사 규칙은 칸 아래 안내로만 적었고, 실제 검사는 서버가 합니다. 요청과 응답은 맨 아래 '기록'에 남습니다.

판매자 준비

대회를 등록하려면 product-service에 승인된 판매자 복제본(PRODUCT_SELLER, status APPROVED)이 있어야 합니다(없으면 403). 복제본은 Kafka 메시지로만 만들어지므로 Redpanda Console(http://localhost:8091) → Topics → 토픽 선택 → Produce Record에서 Value에 아래 JSON을 붙여 넣고 보냅니다. Key는 비워도 됩니다(토픽 파티션 1개).

  • 회원 메시지(queuing.member.joined)를 먼저 보냅니다. 캐시 서비스도 받는 공용 토픽이라, 캐시 서비스가 떠 있으면 캐시 회원도 함께 만들어집니다. 회원 복제본(PRODUCT_MEMBER)이 없으면 판매자 메시지는 다시 시도 없이 건너뜁니다(product-service 에러 로그에만 남음).
  • 그다음 판매자 메시지(queuing.seller.changed, status APPROVED)를 보냅니다.
  • 같은 메시지를 다시 보내도 결과가 같습니다(원본 값으로 덮어씀). 회원 메시지는 저장된 수정 시각(modifyDate)보다 이르면 건너뜁니다. 깨진 JSON이나 모르는 enum 값은 다시 시도 없이 <토픽>.product.dlt로 갑니다.
  • 날짜는 LocalDateTime 형식(yyyy-MM-ddTHH:mm:ss, 시간대 없음)입니다. 아래 값은 이 페이지를 연 시각입니다.

버튼이 부르는 API

    
    
      
  • [등록] POST /api/v1/product/races → 201, 판매 예정(SCHEDULED)으로 저장되고 바로 공개됩니다. 판매 시작일이 오늘로부터 이틀 뒤보다 빠르면 400.
        판매 시작일 0시에 5분마다 도는 상태 배치가 판매 중(ON_SALE)으로 바꾸고, 이때부터 판매 시작 뒤 수정 규칙이 걸립니다.
        판매 상태는 판매자 화면용이고, 자리 확보는 크루 예매 시작·개인 예매 오픈 시각부터 됩니다. 성공하면 대회 ID와 종목별 courseId를 채웁니다.
    • 
      
  • [불러오기] GET /api/v1/product/races/{raceId} → 폼을 채우고, 종목마다 file-service GET /api/v1/file/files?refType=RaceCourse&refId={종목 ID}로 이미지 표를 채웁니다. 취소된 대회는 등록한 회원 ID로만 보입니다(아니면 404).
    • 
      
  • [수정] PUT /api/v1/product/races/{raceId} (등록과 같은 본문). courseId가 있는 종목은 고치고, 없는 종목은 추가하고, 요청에 없는 기존 종목은 뺍니다. 이미지 목록도 통째로 바뀝니다.
        취소된 대회와 판매가 끝난 대회(대회일 다음 날 0시부터)는 수정할 수 없습니다(409).
    • 
      
  • [대회 취소] POST /api/v1/product/races/{raceId}/cancel → 200 "대회를 취소했습니다.", saleStatus CANCELED. 되돌릴 수 없습니다.
    • 
    

  


  

    
대회 정보

    

      
      
      
      
      
      
      
      
      
      
      
      
      
      
    

    
    
      
  • 판매 시작일(saleOpenDate)은 입력하지 않습니다. 크루 예매 시작·개인 예매 오픈 중 이른 날짜로 서버가 채우고, 오늘로부터 이틀 뒤부터 정할 수 있습니다.
    • 
      
  • 일정 기본값은 페이지를 연 날 기준입니다: 개인 예매 오픈 +2일 10:00, 접수 마감 +10일, 대회 +15일 08:00, 환불 기한 +10일.
        날짜가 바뀌어 판매 시작일이 이틀 뒤보다 빨라졌으면 아래 버튼으로 다시 채웁니다.
    • 
      
  • 판매 시작일 0시가 지나면 판매 시작일을 정하는 일정(크루 예매가 있으면 크루 예매 시작, 없으면 개인 예매 오픈)은 바꿀 수 없습니다(409).
        판매 시작 전에 판매 시작일을 바꾸면 이틀 뒤 규칙을 다시 봅니다(400).
    • 
      
  • 이미 지난 판매 일정(크루 예매 시작·마감, 개인 예매 오픈, 접수 마감)을 바꾸거나 일정을 지난 시각으로 옮길 수 없습니다(409).
    • 
    

    

  


  

    
종목 · 참가권

    
    
      
  • 종목은 1개 이상이어야 합니다. 판매 시작 뒤에는 참가비·키트 금액 변경, 정원 줄이기, 참가 조건(거리·종목 구분·노면·제한 시간·나이 제한·키트 포함 여부) 변경,
        티셔츠 사이즈 변경, 종목 빼기를 할 수 없습니다(409).
    • 
      
  • 이미지는 종목마다 붙입니다. 용도를 고르고 파일을 선택하면 file-service(8083)로 ① 업로드 URL 발급 → ② S3에 직접 PUT → ③ 업로드 완료 확인을 하고 fileId를 채웁니다.
        file-service가 dev로 떠 있어야 합니다(dev에만 8085를 허용하는 CORS가 있습니다).
    • 
      
  • 이미지(대표·소개·코스·키트)는 JPG·PNG·WebP 10MB 이하, 소개 영상은 MP4·MOV 100MB 이하입니다(올린 뒤 파일 앞부분으로 형식을 다시 확인합니다).
    • 
      
  • 종목마다 대표 이미지 1장 필수. 최대 개수: 대회 소개 이미지 5, 코스 안내 이미지 7, 키트 이미지 1, 대회 소개 영상 1. 순서(sortNo)는 0 이상.
    • 
      
  • 같은 파일(fileId)은 한 번만 연결됩니다(종목끼리도 안 됨). 위 회원 ID로 올린 파일만 연결되고, 연결은 저장 뒤 Kafka(race.filelink.requested)로 따로 처리되어 실패하면 file-service 로그에만 남습니다.
        올린 뒤 1일 안에 연결되지 않은 파일은 정리 배치가 지웁니다.
    •
