대회 조회·자리 확보 테스트

product-service(8085)의 대회 목록·검색·상세·내 대회 조회와, 주문 서비스가 부르는 내부 API(종목 정보, 자리 확보·판매·복구)를 직접 불러 보는 개발용 페이지입니다(dev 프로파일에서만 열립니다). 요청과 응답은 맨 아래 '기록'에 남습니다.

회원

검색어 · 연관검색어

입력할 때마다 300ms 뒤 GET /api/v1/product/races/suggestions?keyword= 를 부릅니다. 입력한 글자로 시작하는 대회명과 종목명('대회명 종목명')을 각각 5개까지, 공개 목록과 같은 대회(판매 예정·판매 중, 접수 마감 전)에서 찾습니다. 칸을 다 지우면 부르지 않습니다(공백만 넣으면 400 시험). 아래 '공개 대회 목록' 검색에도 이 검색어(keyword)를 씁니다. 대회를 누르면 대회 상세를, 종목을 누르면 대회 상세와 자리 확보 칸을 채웁니다.

대회 (races)

    종목 (courses)

      공개 대회 목록

      GET /api/v1/product/races. 판매 예정·판매 중이고 접수 마감 전인 대회만 나옵니다(판매 중지·판매 종료·취소 대회는 안 나옴). 빈 칸은 보내지 않습니다. 종목 조건(종목 구분·노면·거리·참가비)은 종목 하나라도 맞으면 그 대회가 나오고, minPrice는 조건에 맞은 종목 중 가장 싼 참가비입니다. 검색어 오타는 3~5글자 단어 1글자, 6글자 이상 2글자까지 허용합니다. 행을 누르면 아래 대회 상세를 조회합니다.

      종목 구분 (courseType, 여러 개)

      courseType=KM_10&courseType=HALF처럼 반복해서 보냅니다

      raceId대회명 · 장소지역대회일판매 상태 · 예매 오픈 접수 마감minPrice종목 요약 (이름 · 구분 · 거리 · 참가비 · 남은 개인 자리 · 상태 · 종목 ID)

      대회 상세

      GET /api/v1/product/races/{raceId}. 로그인 없이 볼 수 있지만, 취소된(CANCELED) 대회는 등록한 판매자 회원 ID를 헤더로 보내야 보입니다(아니면 404). 종목 이미지는 상세에 없고 file-service에서 종목마다 받습니다. 남은 개인 자리 = 개인 정원 − 결제 대기 − 판매입니다.

      종목

      종목 ID종목명구분 · 노면거리 · 제한 시간나이참가비 (키트) 티셔츠 사이즈상태 (status)크루 정원 / 남은남은 개인 자리 / 개인 정원

      내 대회

      GET /api/v1/product/races/mine (X-Member-Id 필수, 승인된 판매자만, 아니면 403). 취소된 대회를 포함해 최근 등록 순으로 모두 나옵니다. 정원(quota) = 크루 + 개인 정원, 결제 대기(reserved) = 확보만 하고 결제 전인 자리, 판매(sold) = 판매한 자리입니다. 대회 ID를 누르면 대회 상세를 조회합니다.

      raceId대회명판매 상태대회일접수 마감 종목 ID종목명참가비상태정원 (quota)결제 대기 (reserved)판매 (sold)

      주문용 종목 정보 (내부 API)

      GET /internal/v1/product/courses/{raceCourseId}. 주문 서비스가 부르는 API라 게이트웨이(8000)에는 없고 8085로 직접 부릅니다(헤더 없음). price가 참가권 한 장 값이고 kitPrice는 그 안에 포함된 금액입니다(더하지 않음).

      자리 확보 · 판매 · 복구 (내부 API)

      • 주문 서비스가 부르는 것을 흉내 냅니다. 헤더 없이 부릅니다. 참가 신청 1건 = 자리 1석입니다.
      • [확보] POST /internal/v1/product/holds {raceCourseId, participationId, expiresAt} → data {held, expiresAt}. held=false면 매진입니다(오류가 아니라 200). 대회가 판매 예정·판매 중이고 지금이 개인 예매 오픈 ~ 접수 마감 사이일 때만 됩니다(아니면 409 '접수 기간이 아닙니다.').
      • [판매] POST /internal/v1/product/holds/{participationId}/sell → data {result: SOLD | EXPIRED}. 끝 시각이 지났거나 이미 해제된 자리면 EXPIRED입니다.
      • [복구] POST /internal/v1/product/holds/{participationId}/restore → data {restored}. 판매한 자리를 결제 취소로 정원에 되돌립니다(여러 번 불러도 한 번만).
      • 남은 자리가 0이 되면(결제 대기 포함) 종목 상태가 SOLD_OUT, 다시 생기면 OPEN이 됩니다.

      해제 (Kafka 메시지)

      해제 API는 없습니다. 활성 시간이 끝나면 주문 서비스가 Kafka 토픽 product.hold.cancel로 보냅니다. Redpanda Console(http://localhost:8091) → Topics → product.hold.cancel → Produce Record에서 Value에 아래 JSON을 붙여 넣고 보냅니다(Key는 비워도 됩니다). 보낸 뒤 [대회 상세 다시 조회]로 남은 자리가 돌아왔는지 봅니다. 토픽이 목록에 없으면 product-service가 떠 있는지 확인하세요(구독할 때 만들어집니다). 

      
  
      

  
      
    
      대회 취소 확인
      
    
      POST /api/v1/product/races/{raceId}/cancel (X-Member-Id 필수, 본문 없음) → 200 "대회를 취소했습니다.", data {raceId, saleStatus: CANCELED, saleOpenDate, courseIds}. 되돌릴 수 없습니다.
      
    
        
      
      • 취소한 대회는 공개 대회 목록과 연관검색어에서 빠집니다.
        • 
      
      • 대회 상세는 등록한 판매자만 볼 수 있고('헤더 보내기'를 켜고 그 판매자의 회원 ID), 다른 사람에게는 404입니다. 내 대회에는 취소 상태로 남습니다.
        • 
      
      • 결제 대기 자리(확보만 한 자리)는 해제됩니다. 내 대회의 결제 대기(reserved)가 줄었는지 봅니다.
        • 
      
      • Kafka 토픽 order.race.cancel에 {"raceId", "sellerId", "canceledAt"} 메시지가 나갑니다.
        Redpanda Console(http://localhost:8091) → Topics → order.race.cancel에서 메시지를 확인합니다.
        예: {"raceId": 1, "sellerId": 7001, "canceledAt": "2026-10-13T10:00:00"}
        • 
      
      • 취소한 뒤에는 자리 확보와 대회 수정이 409입니다.
