# 전달문 정리

받는 사람이 다시 묻거나 Claude에게 해석을 맡기지 않도록, 해석을 보내는 쪽에서 끝냅니다. 입력은 원래 자료(대화 내용, 파일, 메모)입니다.

## 머리말 세 줄

모든 전달 자료 맨 위에 둡니다.

```
**할 일:** 결정 / 검토 / 구현 / 참고 중 하나
**결론:** 하고 싶은 말 한 문장
**기한:** 언제까지 필요한지
```

## 순서

1. 할 일, 결론, 기한을 정합니다. 자료에서 확실하지 않은 것은 **추측하지 않고 보내는 사람에게 먼저 묻습니다.** 세 줄이 모두 정해질 때까지 다음으로 가지 않습니다.
2. 파일을 만듭니다. 기본은 `.md`, 요청하면 `.html`입니다. 맨 위에 세 줄, 그 아래에 본문을 둡니다.
   - 본문: 배경(짧게) / 내용 / 결정 또는 검토가 필요한 것(할 일이 결정·검토일 때만)
   - HTML은 외부 CDN 없이 한 파일로 만들고, 세 줄을 맨 위 상자로 보여 줍니다.
   - 저장: 레포 루트 `handoff/YYYY-MM-DD-주제.md`. 루트 `/handoff/`는 `.gitignore`에 있어 커밋되지 않습니다.
3. **슬랙에 붙여 넣을 글**도 출력합니다. 세 줄과 「자세한 내용은 첨부 파일」 한 줄입니다. 슬랙 미리보기에서 세 줄이 바로 보여야 하므로 그 앞에 다른 말을 두지 않습니다.
4. 보내는 사람에게 안내합니다. 파일(.md 또는 .html)을 슬랙에 첨부합니다. 받는 사람이 다시 질문하면 답을 개인 메시지로만 주지 말고 **원래 파일을 고쳐서 다시 올립니다.**

## 문구

- `CONTEXT.md`의 용어를 따릅니다.
- 줄임말, 영어 상태값, 코드 이름, 우리끼리만 아는 말 대신 뜻을 씁니다.
- "→ 그래서 무슨 일이 생기는지"까지 씁니다.
- 비유와 번역체는 쓰지 않습니다.
- 읽는 사람이 대화 맥락을 모른다고 가정하고 씁니다.

완료 기준: 세 줄이 모두 채워져 있고, 파일 경로와 슬랙 글이 출력되었습니다.
